## Released integration surface

- **SDK:** `@earendil-works/pi-coding-agent` supports Node.js and Bun, with one conversation per `createAgentSession()`. The package requires Node >=22.19.0; Bun compatibility is documented but not executed here. Model runtime, settings, resource loading, tools and session manager are injectable. [SDK](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/sdk.md) [Package manifest](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/package.json)
- **RPC:** a long-lived child process exchanges commands/responses/events as LF-delimited JSON. It is suitable for a Java/Spring host; a separate TypeScript service is not inherently required. It is neither an HTTP API nor a sandbox. Command IDs correlate responses; ordinary session events generally lack those IDs. Hosts must drain stdout, handle stderr, exits and deadlines, and isolate each user's conversation. [RPC](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc.md)
- **Models:** model/provider selection, thinking levels, compatible endpoints and custom provider extensions exist. The bundled catalog can receive newer catalog overlays, so package pinning alone does not pin model choice or prices. Explicit provider/model and controlled runtime credentials are necessary for reproducibility. Availability and provider commercial/data terms were not verified. [Models](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/models.md)
- **Custom tools:** `customTools` registers definitions and `tools` controls activation. JSON Schema validation includes coercion; it is not domain authorization. Tools receive cancellation signals and can publish updates. Extension hooks can block calls; modified inputs are not revalidated after hook mutation. Revalidate business constraints in the Goldy's service regardless. [SDK source](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/src/core/sdk.ts) [Extensions](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/extensions.md)
- **Skills:** metadata advertises instructions; the model loads full instructions when needed, with explicit `/skill:name` available. `.agents/skills` ancestor discovery stops at the repository root. `disable-model-invocation` supports explicit-only skills. Skill selection is fallible, and skills do not confer authorization. [Skills](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/skills.md)
- **Extensions:** executable modules run inside Pi with its OS privileges and can inspect prompts, files, credentials and history. They register tools and lifecycle hooks. Project trust gates selected resource loading; it is not an execution boundary. [Extensions](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/extensions.md) [Security](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/security.md)

## Streaming, steering and stopping

Subscribe before prompting. SDK events include cumulative objects; the RPC JSON representation uses deltas and final authoritative messages. `message_end` is the completed message; `agent_end` ends only one low-level run. **`agent_settled`** is the session-level signal that retries, compaction recovery and queued messages will not automatically continue. A successful RPC prompt response is admission/handling, not completion; `handled` can mean no run starts at all. [Events](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/json.md) [RPC](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc.md)

Steering enters after the current assistant turn's tools, before the next model request. Follow-ups wait until current pending work finishes. Neither should be represented as immediate cancellation. RPC **`clear_queue` before `abort`** implements stopping queued and active work: abort alone can continue remaining queued messages. Abort waits for idle; separate bash operations have `abort_bash`. SDK disposal aborts and removes listeners. Goldy's must also stop admissions and cancel its backend query/export jobs; Pi signals do not prove an external operation stopped. [RPC commands](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc-commands.md) [SDK](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/sdk.md)

## Session state and Postgres ownership

The released SDK supports an externally stored tree **without temporary JSONL files**:

```typescript
// Adapter outline, source-verified but not executed.
const snapshot = {
  piVersion: "1.5.2",
  entries: [manager.getHeader(), ...manager.getEntries()],
  leafId: manager.getLeafId(),
};
// Validate a non-null header and snapshot structure before serializing.
const restored = SessionManager.inMemory(cwd, undefined, snapshot.entries);
if (snapshot.leafId === null) restored.resetLeaf();
else restored.branch(snapshot.leafId);
// Supply restored as createAgentSession({ sessionManager: restored, ... }).
```

`getEntries()` excludes the header; `getHeader()` can return null. `inMemory(cwd, options?, entries?: FileEntry[])` loads externally held entries. Loading reconstructs the leaf from entry order, whereas `branch()` can move it without appending, so persist the active leaf separately. Include the **whole tree**, compaction entries and context edits, not just displayed messages. `getEntries()` returns a shallow copy; serialize a coherent snapshot under the adapter's session serialization discipline. [SessionManager source](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/src/core/session-manager.ts)

**Design inference:** Spring/Postgres can be the sole durable authority for versioned Pi snapshots, ownership, job state and the user-visible transcript projection. The worker can use an in-memory session restored from that snapshot, with no independently durable Pi files. Persist snapshot and transcript projection in the same application transaction/revision, using single-writer ownership or revision checks. Treat live stream deltas as provisional until the corresponding checkpoint is committed. Do not claim the ordinary event callback is itself a transaction with Postgres: the adapter must define and test checkpoint ordering, retries and failure behavior. The manager is authoritative for reconstructed model context; assigning `session.agent.state.messages` does not replace it. [SDK](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/sdk.md) [SessionManager source](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/src/core/session-manager.ts)

**Limit:** a serialized history tree is not a live execution checkpoint. Queued inputs, running tools and arbitrary extension/process state are not covered by the above snapshot. A worker crash should produce an interrupted job that the host reconciles, rather than an unqualified promise of automatic exactly-once continuation. A tool or export may finish after the last stored checkpoint; Goldy's needs job IDs, effect idempotency and explicit restart behavior. This is a design consequence of the session-manager scope, not a Pi durability guarantee. [SessionManager source](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/src/core/session-manager.ts)

Compaction stores a summary and retained-entry boundary, rebuilding context from summary plus retained messages. Raw omitted entries remain stored. Therefore compaction is neither deletion nor permission revocation: snapshots, summaries, exports and historical projections can all retain sensitive material. Permission downgrade requires a host policy for denying/rebuilding old context. [Compaction](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/compaction.md)

## Explicit analytics configuration

Use a custom `ResourceLoader` supplying only reviewed resources, in-memory settings, explicit model runtime/credential paths and an in-memory session manager. The release's full-control example demonstrates replacing discovery. Supply a literal allowlist of approved custom tool names; `+name`/`-name` lists modify defaults instead of replacing them. Built-in defaults are read/bash/edit/write. `noTools: "builtin"` still allows extension/custom tools, so it is not a complete allowlist. SDK sessions do not automatically add the CLI's codemode, tool-search and MCP built-ins. Do not add them for scoped analytics. Assert active tools during the acceptance spike. [Full-control example](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/examples/sdk/12-full-control.ts) [SDK source](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/src/core/sdk.ts) [SDK](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/sdk.md)

Declining project trust alone is insufficient: context files such as AGENTS.md still load unless disabled, and the project session-directory lookup occurs before trust resolution. A working directory does not restrict filesystem access. Avoid owner home/config discovery and do not expose raw RPC to managers because it includes administrative and bash commands. Even a trusted custom loader does not sandbox its own code; OS/container/network boundaries remain necessary. [Security](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/security.md) [RPC commands](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc-commands.md)

## Durable is separate and experimental

`@earendil-works/pi-durable` exists in the same v1.5.2 tag, but prominently declares its API experimental and subject to change between releases. It is a separate harness built over pi-ai and Chord, not an option that automatically makes `AgentSession` durable. It persists conversations, tasks and checkpoints and can resume unfinished tasks. Request IDs deduplicate submissions; cancellation of a wait does not cancel its work. [Durable README](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/durable/README.md) [Durable manifest](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/durable/package.json)

A crash-interrupted tool reruns only when marked `replay: "safe"`; otherwise it yields an interrupted result. External effects still require idempotency even for replay-safe tools. Background-owned tasks can survive a parent's abort, so stopping all work requires the appropriate scope. These are task ownership rules, not application user authorization. [Durable README](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/durable/README.md)

Storage options include memory, JSONL, SQLite, IndexedDB and Cloudflare Durable Object adapters. SQLite uses WAL with synchronous NORMAL: process-crash recovery is distinct from power-loss durability. JSONL offers `fsync: true` and also keeps history in memory. Storage errors terminate the harness rather than transparently retrying; code ignoring abort can delay close. These details rule out treating the package as a complete managed/distributed job service. [Durable README](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/durable/README.md)

## Recommendation and acceptance boundary

For a bounded reporting-first evaluation, use pinned coding-agent SDK with explicit resources and typed Spring reporting/export tools. The Node/Bun adapter is a runtime integration choice; compare its operational cost against Spring-owned RPC before committing to a new production service. Keep Spring identity, semantic calculations and RBAC authoritative. Use Postgres-owned history snapshots and explicit interrupted-job behavior first. Evaluate Durable only if automatic crash continuation is a concrete requirement and its separate storage/task model is justified.

Before implementation acceptance, run snapshot round trips (branches, null leaf, compaction, tool results and context edits), default-resource/tool denial tests, streamed completion versus acceptance tests, clear-queue/abort races, permission downgrade/history tests, worker-loss checkpoints, effect idempotency and pinned-runtime compatibility. None was executed in this research. No credentials, real environment files or production data were accessed. Material risks are experimental durability APIs, catalog drift, snapshot/stream transaction gaps, sensitive retained history and extension execution privileges.
