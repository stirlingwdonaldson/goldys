# Ask workspace: data and security research

**Historical research evidence.** The subsequent [accepted workspace decision](../decisions/0002-pi-agent-workspace.md) and [updated proposal](ask-goldys-pi-workspace-proposal-2026-11-15.md) govern the implementation direction where they supersede recommendations below. Source observations remain evidence, not runtime acceptance.

Date: 15 November 2026. Scope: repository evidence and a proposed contract for a Pi-backed workspace. No source system, production database, credentials, live model or runtime integration was accessed. Proposed interfaces below are design recommendations, not accepted implementation or additional permissions.

## Decision

Keep Goldy's Java application authoritative for identity, permission checks, business definitions and data retrieval. A replacement orchestration runtime can plan and present, but must receive only authorized, bounded, typed results. Do not hand it a database connection, raw ledger, source credentials, SQL tool or a filesystem copy of business tables. This preserves the accepted governed-planning direction without confusing runtime migration with permission expansion. Weekly reporting/export priority and the ban on generic AI SQL remain explicit product constraints. [PRD](../prd.md), [SRS](../srs.md), [accepted decision](../decisions/0001-governed-conversational-planning.md), [architecture invariants](../../.claude/rules/architecture-invariants.md).

The compiler authorizes datasets, relationships and selected fields, plus every field in predicates, grouping and ordering before compilation. Hiding a salary/cost field from SELECT alone is therefore insufficient and would regress the existing model. Limits are 1,000 rows, two joins, 20 selections/groups/order terms and filter depth eight; values are bind parameters. Parent aggregates crossing a one-to-many relationship are rejected, including counts/averages: distinct amounts are not a safe substitute for distinct business facts. `RelationalQueryService` returns source-basis, aggregation coverage and truncation notices. These protections are reusable, but not proof of ontology correctness. [QueryCompiler](../../backend/src/main/java/com/goldys/platform/query/QueryCompiler.java), [RelationalQueryService](../../backend/src/main/java/com/goldys/platform/query/RelationalQueryService.java), [integration tests](../../backend/src/test/java/com/goldys/platform/query/RelationalQueryIntegrationTest.java).

Important boundary detail: `QueryPlan` stores dataset/join names as strings and the registry validates them; this is bounded internally, but it is not the existing AI enum schema. Exposing the record verbatim would change the AI boundary, and advertising every field aggregation as a metric would create competing calculation definitions. The current rule forbids arbitrary field names/free-text filter expressions; the accepted decision requires semantic alignment and reviewed relationships/filters before extension. [QueryPlan](../../backend/src/main/java/com/goldys/platform/semantic/query/QueryPlan.java), [tool contract](../contracts/ai-tool-boundary.md).

## Proposed broad discovery and retrieval contract

These are proposed interface shapes, not code names already present:

1. **Discover concepts:** bounded `ConceptKind`/domain enums and optional explicit `MetricId` or approved evidence-dataset IDs. Return approved definition/version, units, valid grains/dimensions, authorized relationships, source/read mode and supported operators. Accessible discovery may omit unavailable concepts; explicit denied selections fail. Definition availability must remain separate from data coverage. Never return physical table/column names or connector authentication details.
2. **Execute governed plan:** a versioned union of `MetricAnalysisPlan` and `EvidenceQueryPlan`. Metric nodes use `MetricId` and existing `MetricQuery` semantics; evidence nodes use reviewed dataset/field/relationship IDs generated as closed enums, typed predicate operators/values and existing row/complexity bounds. No SQL, scripts, formulas, arbitrary identifiers, free-text filters or raw paths. Maintain an explicit allowlist of supported evidence plans rather than passing the entire internal registry through unchanged.
3. **Resolve semantics before combining:** reviewed relationships declare grain, multiplicity, source identity bridge, measure basis, cost/tax basis, population, allowed joins and effective dates. A cross-domain comparison may return separate qualified series without implying a valid join. Derived business measures remain implemented by the semantic calculation path; row arithmetic or model prose cannot invent a second COGS, margin or labour definition.
4. **Return evidence envelopes:** immutable result ID, definition version, normalized scope, current authorization dependencies, execution time, basis/read mode, units, coverage, provenance, null reasons and truncation. Any artifact/citation references the envelope. Saved analyses persist configuration; reopened execution reauthorizes. Issued report snapshots are a separate versioned product contract, not an accidental chat cache.
5. **Authorize at every use:** derive user identity server-side; check each operand before execution, before exporting/attaching results, before retrieving saved artifacts and before including history in a model context. Runtime-supplied role claims or result IDs do not confer access. Make denial visible and do not silently substitute a cheaper accessible metric.

This allows many questions through a small family of typed tools, avoiding one-tool-per-question growth. Adoption requires updating the AI boundary contract, registry-to-metric semantic mappings, and accepted relationship/filter definitions; it does not require approving generic SQL. [governed decision](../decisions/0001-governed-conversational-planning.md), [SRS report and authorization contracts](../srs.md), [architecture rules](../../.claude/rules/architecture-invariants.md).

## Stored context is a separate security boundary

`ConversationService` correctly scopes CRUD/context by authenticated account ownership and reconstructs history server-side. However, `contextFor`/`buildContext` replay persisted assistant text and a running summary without checking the underlying business resources. `get` returns historical messages using ownership alone. `complete` stores prose plus tool trace; a thread summary is subsequently wrapped as `SystemMessage`. Thus new tool authorization alone does not prevent previously visible sensitive data from reentering context after permission changes, and summary text currently gains system-message placement. This is a source inspection finding, not a demonstrated production exploit. [ConversationService](../../backend/src/main/java/com/goldys/platform/conversational/ConversationService.java), [message schema](../../backend/src/main/resources/db/migration/V27__conversation_threads.sql).

For a workspace, store typed scope/provenance and resource dependencies with retained evidence, reauthorize before context assembly and artifact retrieval, and avoid promoting document text or summaries to policy instructions. If old prose cannot be reliably separated from sensitive facts, withhold it after a relevant permission change and explain why; do not ask the model to redact its own forbidden input. Threads, summaries, forked chats, artifact previews, export downloads and search indexes need the same lifecycle treatment. Ownership and access to underlying financial data are separate checks. This is a proposed security completion requirement for the expanded surface, not a claim the current implementation already enforces it.

## Salary inference and manager access

The catalogue exposes wages-only `LABOUR_COST` under `labour.cost`, alongside scheduled/actual hours and department grouping. It explicitly excludes super and other employment components pending confirmation. Transitive operand authorization prevents a derived ratio from bypassing cost permission, but that is not statistical disclosure control. Narrow day/department slices or differencing overlapping groups could reveal an individual's rate when combined with staffing knowledge. No cohort-size, differencing budget or inference-control contract was identified in the inspected catalogue/compiler. Do not claim those guarantees. [MetricCatalog](../../backend/src/main/java/com/goldys/platform/semantic/catalog/MetricCatalog.java), [current-state permissions](../architecture/current-state.md), [SRS outstanding labour/permission decisions](../srs.md).

Keep new individual-pay fields and joins unavailable pending explicit mapping. Before supporting manager workspace access, agree resource/field/department grants and whether small-cohort aggregates require suppression or a stricter cost grant. Such thresholds are stakeholder policy, not values to invent. Revoked permissions must also remove usable salary information from saved evidence/context; aggregate grants alone do not authorize person-level data.

## Data capability is not source readiness

- Deputy webhook ingestion remains raw-only until payload schema confirmation. A richer runtime cannot produce reliable labour forecasts, full employment cost or weekly prime cost from that gap. Real samples/schema and measured parser hit rates are prerequisites to dependent source implementation. [source access](../connectors/source-access.md), [PRD labour scope](../prd.md).
- OpenTable requires an assisted owner sign-in or supported rich CSV exports; partner API access is not assumed. CTB uses authenticated internal endpoints, not a public API. Some recipe/ingredient methods remain unverified, and older flattened captures cannot reconstruct complete snapshots. [source access](../connectors/source-access.md).
- Source-cost estimates are not validated actual COGS. Invoice replacement/deletion semantics and individual PDF discrepancies remain unresolved; historical cost effectiveness, mappings and source coverage must remain qualified. Transaction-specific costing needs a source identity bridge. [source access](../connectors/source-access.md), [current state](../architecture/current-state.md), [SRS cost/prime-cost contracts](../srs.md).
- Only explicitly approved invoice/line and CTB product-sale evidence may use `CANONICAL_DIRECT`; there is no general canonical/raw exception. Reads elsewhere remain resolved-through-semantic. [architecture invariants](../../.claude/rules/architecture-invariants.md), [system context](../system-context.md).

## Uploads, retention and deletion

Every ingested payload, including PDFs/manual input, must land byte-faithfully in `raw_record` before parsing, with SHA-256 and byte length; database append-only protection prohibits row update/delete. Derived JSON is not authoritative. A workspace attachment cannot quietly become disposable evidence in an agent sandbox if used as a business source. [raw invariant](../../.claude/rules/architecture-invariants.md), [V2 ledger](../../backend/src/main/resources/db/migration/V2__ingestion_ledger.sql), [RawPayloadService](../../backend/src/main/java/com/goldys/platform/ingestion/RawPayloadService.java).

The current conversation deletion cascade applies to chat messages, not the raw ledger. Retention/recovery targets remain unresolved in SRS. Therefore do not promise that deleting a chat removes an ingested document, nor promise arbitrary automatic retention deletion. Before attachment implementation, decide whether an attachment is ingested evidence or transient conversational context. If a transient non-ledger class is desired, explicitly review its relationship to the all-ingested-payload invariant before building it. Define retention, permitted content, visibility, model transmission and deletion semantics for both classes. An ingest-on-confirmation workflow can make the distinction clear, but is a proposed policy, not an existing exemption. [V27](../../backend/src/main/resources/db/migration/V27__conversation_threads.sql), [SRS outstanding decisions](../srs.md).

Proposed implementation controls: opaque attachment IDs, owner/resource-scoped downloads, bounded size/type/parser work, provenance from original bytes, no executable attachment contents, and separate stored derivatives/artifacts. Agent file paths must not become authorization tokens. These are design recommendations, not existing verified attachment behavior.

## Schema and tests affected by implementation

No schema or production code changes were made for this research. Future work should use new Flyway migrations, never modify applied versions:

- Existing `conversation_thread`/`conversation_message` (V27): add structured analysis scope and permission/provenance dependencies or related evidence/context tables; retain ownership boundaries. Workspace artifacts/attachments require explicit owner, lifecycle, evidence references, status and immutable version relationships. Do not duplicate authoritative raw bytes into an ungoverned session store.
- Existing `saved_query`/revision tables (V89) and dashboard configuration: reuse configuration/version concepts where appropriate, keeping issued reports and chat artifacts distinct. Changes to query allowlists may require new `goldys_ro` grants following V88/V90/V91/V94; never broad database privileges.
- New resources: owner-only permission seed rows. Manager grants need the unresolved mapping. Preserve V105 account constraints unless manager provisioning is separately approved.

Existing tests to extend: [PermissionServiceTest](../../backend/src/test/java/com/goldys/platform/auth/PermissionServiceTest.java), [ToolDispatcherTest](../../backend/src/test/java/com/goldys/platform/reporting/ToolDispatcherTest.java), [GovernedAnalysisTest](../../backend/src/test/java/com/goldys/platform/reporting/GovernedAnalysisTest.java), [MetricCatalogTest](../../backend/src/test/java/com/goldys/platform/semantic/catalog/MetricCatalogTest.java), [RelationalQueryIntegrationTest](../../backend/src/test/java/com/goldys/platform/query/RelationalQueryIntegrationTest.java), [SavedQueryIntegrationTest](../../backend/src/test/java/com/goldys/platform/query/SavedQueryIntegrationTest.java), [ConversationServiceTest](../../backend/src/test/java/com/goldys/platform/conversational/ConversationServiceTest.java), [IngestionLedgerSchemaTest](../../backend/src/test/java/com/goldys/platform/ingestion/IngestionLedgerSchemaTest.java), [ArchitectureBoundariesTest](../../backend/src/test/java/com/goldys/platform/architecture/ArchitectureBoundariesTest.java).

Acceptance cases: forbidden metadata/explicit metric denial; forbidden predicate/order/group/join operands; derived-cost operand denial; deny before executing any node; unknown identifier/injection rejection; fanout/limit/timeout behavior; current account/permission changes between plan, execution and artifact access; cross-owner thread/artifact access; revoked historical context; malicious uploaded instructions kept as data; deletion preserving immutable evidence; missing-vs-zero/source-qualified outputs. ## Approval map and limits

Already accepted: governed concept composition, authoritative calculations in application code, reviewed extensions, explicit denial, metadata/follow-up/saved-analysis authorization, no generic AI SQL, no executable AI UI, no source write-back, and source-evidence exception limited to named domains. These need preservation, not reapproval.

Decisions still required for an implementation that needs them: manager grants/provisioning and inference policy; additional approved concepts/relationships/filters; attachment ingestion classification and retention/deletion; persistent workspace data/model exposure policy; any new canonical-direct exception. Production operations, source recovery/config changes, live-model experiments, publishing/push/merge and deployment retain their separate authorization gates. This proposal authorizes none of them. [AGENTS](../../AGENTS.md), [decision](../decisions/0001-governed-conversational-planning.md), [SRS](../srs.md).

Skipped/not checked: live source readiness, actual grants or production contents, end-to-end Pi isolation, provider retention, runtime package behavior and performance. Material risk: migrating orchestration while replaying unclassified prose/artifacts would preserve tool gates but leave historical-data disclosure and provenance gaps unresolved.
